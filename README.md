# AMC AI

AMC (Adaptive Memory Compute) — экспериментальная нейросеть на Java. В проекте два эксперимента: синтетические задачи SET/GET с адресуемой памятью и генерация коротких Java-методов.

## Генерация Java-методов

Модель кодирует описание и сигнатуру, переносит рекуррентное состояние между выходными токенами и предсказывает следующий токен до признака конца. Можно обучить одну модель на всех задачах или запускать разделы по отдельности.

### Целые Java-классы

Ход работы с внешним корпусом и разбиение Exercism описаны в [плане обучения](research/java-training-plan.md).

Флаг `TrainPrograms --bpe` включает подсловную токенизацию UTF-8 для выходного исходника. Правила слияния сохраняются вместе с весами. Флаг `--stop-on-repeat` у `GenerateProgram` и `JavaProgramBenchmark` досрочно завершает циклическую генерацию и сообщает причину остановки.

Экспериментальный режим `--scaffold` у этих трёх команд работает с корпусом, где рядом с `prompt.txt` есть `Starter.java`. Модель генерирует добавочные импорты, вспомогательные члены и тела методов-заглушек. Сборщик оставляет декларации стартового класса в исходном виде и проверяет синтаксис правок до запуска тестов. Используйте отдельный чекпойнт, обученный с `TrainPrograms --scaffold`.

`TrainPrograms --scaffold --attention` и `TrainPrograms --bpe --attention` добавляют обучаемое внимание к тексту задачи. При генерации каждого токена рекуррентное состояние задаёт веса известных слов и символов из задания. Для запуска используйте обычные команды генерации и бенчмарка с файлом весов этого эксперимента. Каркасному чекпойнту нужен флаг `--scaffold`. [Команды и результаты эксперимента](research/java-training-plan.md#обучаемое-внимание-в-amc).

Режим `--body` обучает генерацию операторов для одного метода-заглушки. AMC сам добавляет внешние скобки, вставляет реализацию в `Starter.java` и проверяет синтаксис. Флаг поддерживается командами обучения, генерации и проверки. [Сравнение форматов и команды запуска](research/java-training-plan.md#обучение-на-телах-методов).

`JavaBodyScaleCorpus` генерирует и проверяет два вложенных синтетических корпуса для `--body`. Скрипт `compare-java-body-scale.ps1` сравнивает обучение на 250 и 1 000 задачах при совпадающем числе обновлений. [Воспроизведение эксперимента](research/java-training-plan.md#масштаб-корпуса-для-тел-методов).

Отдельная модель получает описание и генерирует содержимое `Solution.java` целиком. Токенизация сохраняет пробелы, переносы, кавычки и знаки Java. Латинские идентификаторы можно составлять из отдельных символов. Словарь расширяется символами из обучающего корпуса. Режим использует отдельный формат весов, а прежние файлы моделей методов по-прежнему загружаются.

Корпус находится в `datasets/java-programs`. Каждая задача оформлена каталогом с `prompt.txt` и `Solution.java`. В `test/<id>` также нужен `Verify.java` с проверками в `main`. Тренер читает только `train/`. Бенчмарк проверяет пересечения идентификаторов, описаний и одинаковых исходников с учётом различий в форматировании. Встроенный корпус содержит 16 обучающих классов и восемь отложенных задач по состоянию объектов, интерфейсам, generics, исключениям, Stream API, NIO, records и `CompletableFuture`.

В IntelliJ IDEA доступны **AMC Java Programs Train**, **AMC Java Programs Generate** и **AMC Java Programs Benchmark**. Для бенчмарка нужен Linux-режим Docker и локальный образ `eclipse-temurin:21-jdk`. Каждая проверка использует отдельный контейнер без сети, компилирует под Java 21 и запускает проверочный класс с ограничениями памяти и времени. [Образ Temurin](https://hub.docker.com/_/eclipse-temurin) · [Параметры Docker](https://docs.docker.com/reference/cli/docker/container/run/).

```powershell
.\scripts\build.ps1
docker pull eclipse-temurin:21-jdk
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.training.TrainPrograms
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.training.GenerateProgram datasets/java-programs/train/generic-first/prompt.txt
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.benchmark.JavaProgramBenchmark datasets/java-programs --reference
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.benchmark.JavaProgramBenchmark
```

Обучение по умолчанию выполняет 600 эпох и сохраняет лучший по обучающей ошибке чекпойнт в `results/java-programs.bin`. Аргументы тренера — `[корпус] [файл весов] [эпохи] [seed]`. Корпус с тем же форматом можно передать без изменений исходников. Предел текущего режима — один исходник размером до 2047 токенов.

В прогоне на Temurin 27 с seed 42 выбран чекпойнт на 575-й эпохе. Средняя обучающая ошибка на токен снизилась с 4,541630 до 0,012991. Модель точно воспроизвела 16 из 16 обучающих исходников. На восьми отложенных задачах результат — 0 из 8. Семь генераций завершились ошибками компиляции, одна достигла предела длины. Все восемь эталонов отложенной выборки скомпилировались и прошли проверки в Docker. Этот результат измеряет запоминание небольшого корпуса, поэтому режим остаётся исследовательским.

### Генерация через локальную кодовую модель

`scripts/generate-java-local.ps1` работает в PowerShell 7 и обращается к локальному серверу с API `/v1/chat/completions`. Для первого прохода модель получает описание и стартер из `prompt.txt`. Бенчмарк проверяет полученные файлы в тех же контейнерах, что и решения AMC. `--feedback` сохраняет статус и до 4 КиБ диагностики компилятора или тестов. Повторный проход с `-RepairFrom` сохраняет прошедшие решения и делает одну новую попытку на каждое оставшееся задание. [Документация llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md).

Пример для Qwen2.5-Coder 1.5B Instruct Q4_K_M. При первом запуске сервер скачает около 1,12 ГБ весов в локальный кэш. Подготовьте исходный корпус и зависимости JUnit по инструкции к импорту. [Карточка модели](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF) · [Подготовка корпуса](research/java-training-plan.md#воспроизведение-первого-импорта).

```powershell
.\scripts\build.ps1
.\scripts\import-exercism.ps1 -ExpandedTraining -Destination build/java-exercism-scaffold
docker pull eclipse-temurin:21-jdk
$cache = (New-Item -ItemType Directory -Force build/amc-llama-cache).FullName
docker run -d --rm --name amc-java-model --cap-drop ALL --security-opt no-new-privileges `
  -e LLAMA_CACHE=/cache --mount "type=bind,source=$cache,target=/cache" -p 127.0.0.1:8091:8080 `
  ghcr.io/ggml-org/llama.cpp@sha256:c2cf6c72d913b6c89a5f0929f2a866e6161e09e7dc187e0f3b0f21e923e26db3 `
  --host 0.0.0.0 --port 8080 -hf Qwen/Qwen2.5-Coder-1.5B-Instruct-GGUF:Q4_K_M `
  --alias amc-qwen-local -t 6 -c 4096 --parallel 1
```

Когда `Invoke-RestMethod http://127.0.0.1:8091/health -NoProxy` вернёт `status: ok`, запустите генерацию и проверку. Для нового прогона выберите свободные каталоги вывода.

```powershell
$java = Join-Path $env:JAVA_HOME 'bin/java.exe'
$corpus = 'build/java-exercism-scaffold'
$first = 'build/java-local-validation'
$repaired = 'build/java-local-validation-repair'
.\scripts\generate-java-local.ps1 -Corpus $corpus -Destination $first -Model amc-qwen-local
& $java -cp build/classes dev.amc.benchmark.JavaProgramBenchmark --candidates --feedback $corpus $first validation
.\scripts\generate-java-local.ps1 -Corpus $corpus -Destination $repaired -Model amc-qwen-local -RepairFrom $first
& $java -cp build/classes dev.amc.benchmark.JavaProgramBenchmark --candidates $corpus $repaired validation
docker stop amc-java-model
```

### Общий прогон

**AMC Java Course Train** обучает с нуля одну модель на 464 англоязычных описаниях за 80 эпох и сохраняет веса в `results/java-course.bin`. В обучении перемешиваются задания из четырёх разделов. Для общего режима используются ширина ядра 48, seed 42 и шаг Adam 0,001.

| Раздел | Что генерирует модель | Указание для генератора |
| --- | --- | --- |
| Арифметика | Две операции над параметрами `int` и константой | Без флага |
| Массивы | Подсчёт, сумма и сумма квадратов с фильтрацией | `--arrays` |
| Строки | Подсчёт, первый и последний индекс символа по условию | `--strings` |

В IDEA **AMC Java Course Generate** загружает общий файл весов и печатает метод для списка. Чтобы попробовать другой раздел, измените флаг и описание в **Program arguments**. **AMC Java Course Benchmark** проверяет все четыре раздела по этому же файлу весов. Для каждого раздела оценка разделена на новые значения внутри знакомых сочетаний и полностью отложенные сочетания операций. Проверка запускает только ограниченный набор числовых и символьных выражений, один проход по входным данным и разрешённые операции со строкой или `HashSet`.

### Двухшаговая арифметика

Модель дописывает тело метода `static int solve(int x, int y)`. Задачи ограничены двухшаговыми целочисленными выражениями с `+`, `-` и `*`. Обучение использует 98 примеров из семи семейств.

В IntelliJ IDEA с JDK 27 запустите **AMC Java Train**, затем **AMC Java Generate** или **AMC Java Benchmark**. Обучение сохраняет словари и веса в `results/java-code.bin`. В конфигурации **AMC Java Generate** второй аргумент — описание задачи.

Из PowerShell с JDK 27 в `JAVA_HOME`:

```powershell
.\scripts\build.ps1
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.training.TrainJava
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.training.GenerateJava results/java-code.bin 'First add x and y. Then multiply the result by 3.'
& "$env:JAVA_HOME\bin\java.exe" -cp build/classes dev.amc.benchmark.JavaCodeBenchmark
```

`TrainJava` принимает позиционные аргументы `[файл-весов] [эпохи] [seed]`. По умолчанию используются 80 эпох и seed 42. В `JavaCodeBenchmark` можно передать другой файл весов или `--initial` для оценки модели с исходной инициализацией.

Бенчмарк считает `pass@1` отдельно для новых числовых литералов внутри известных семейств и для двух полностью отложенных сочетаний операций. Для каждого задания берётся одна генерация. Разрешённое тело из одного арифметического `return` компилируется под Java 21, затем проверяется на девяти наборах аргументов в отдельном JVM-процессе с таймаутом. Результат характеризует этот набор арифметических задач.

На Temurin 27 с seed 42 после 80 эпох средняя обучающая cross-entropy на токен упала с 1,099799 в первой эпохе до 0,000061 в последней.

| Выборка | Скомпилировалось после обучения | Прошло все проверки до обучения | Прошло все проверки после обучения |
| --- | ---: | ---: | ---: |
| Новые литералы в известных семействах | 28/28 | 0/28 | 28/28 |
| Полностью отложенные семейства | 36/36 | 0/36 | 10/36 |

Все 10 решений в отложенных семействах относятся к «умножить, затем прибавить». В семействе «сложить, затем вычесть» все 18 методов скомпилировались, но вернули неверный результат.

## Как устроен эксперимент SET/GET

Для команды `SET(k, v)` модель записывает `tanh(E[:, v])` в ячейку с индексом `k`. Новая запись по тому же ключу заменяет предыдущую. Команда `GET(k)` читает эту ячейку напрямую. Ключ служит заданным индексом, а градиент проходит через вектор выбранного значения. Adam обновляет эмбеддинги значений, веса рекуррентного ядра и декодера.

Рекуррентное ядро использует общие веса для фиксированного числа шагов (`--steps`, по умолчанию 2). Обучаемая адресация и адаптивная остановка описаны в [плане исследований](research/roadmap.md).

- `amc-core` содержит скалярный autodiff, модель, Adam, генератор SET/GET и формат весов.
- `amc-training` обучает модель и считает метрики на проверочной и тестовой выборках.
- `amc-benchmark` замеряет время предсказания на CPU для обоих режимов.

## Сборка и тесты

Для сборки с целевой версией Java 27 укажите JDK 27 в `JAVA_HOME` и запустите Maven из корня репозитория.

```text
mvn -Pjava27 clean verify
```

На JDK 21 и выше доступна сборка с целевой версией 21 через `mvn clean verify`. Maven запускает тесты JUnit во всех трёх модулях, включая проверку градиентов конечными разностями, перезапись ячеек, восстановление весов и контрольный прогон обучения.

Обёртки для Maven — `./scripts/test.sh -Pjava27` и `.\scripts\test.ps1 -Pjava27`. Скрипты обучения и замеров компилируют код с помощью `javac` и запускают его без Maven. Они используют JDK из `JAVA_HOME` или из `PATH`, если переменная не задана. Пути к весам считаются относительно текущего каталога.

## Воспроизводимый запуск

### IntelliJ IDEA

Откройте корневой `pom.xml` как Maven-проект и выберите JDK 27 в **File → Project Structure → Project SDK**. В меню запуска на верхней панели доступны четыре конфигурации.

- **AMC Train** выполняет 600 обновлений и сохраняет веса в `results/amc.bin`.
- **AMC Train Baseline** выполняет 600 обновлений и сохраняет веса в `results/baseline.bin`.
- **AMC Benchmark** измеряет оба режима на начальных весах.
- **AMC Benchmark Trained** загружает оба файла из `results/`. Для их создания запустите обе конфигурации обучения.

### Командная строка

Windows PowerShell

```powershell
.\scripts\train.ps1 --epochs=600 --save=results/amc.bin
.\scripts\train.ps1 --epochs=600 --baseline --save=results/baseline.bin
.\scripts\train.ps1 --epochs=0 --load=results/amc.bin
.\scripts\benchmark.ps1 results/amc.bin results/baseline.bin
```

Linux/macOS

```bash
./scripts/train.sh --epochs=600 --save=results/amc.bin
./scripts/train.sh --epochs=600 --baseline --save=results/baseline.bin
./scripts/train.sh --epochs=0 --load=results/amc.bin
./scripts/benchmark.sh results/amc.bin results/baseline.bin
```

| Параметр обучения | По умолчанию | Назначение |
| --- | ---: | --- |
| `--epochs` | 1200 | Количество обновлений Adam, по одному примеру на шаг. Значение 0 запускает только оценку. |
| `--keys`, `--values` | 4, 4 | Размеры множеств ключей и значений. |
| `--writes` | 6 | Число операций SET перед GET. |
| `--hidden`, `--steps` | 12, 2 | Ширина ядра и фиксированное число рекуррентных шагов. |
| `--seed` | 42 | Инициализация весов и генераторов выборок. |
| `--test-samples` | 1000 | Размер отдельной тестовой выборки. |
| `--baseline` | | На вход ядра поступает эмбеддинг значения последней операции SET независимо от запрошенного ключа. |
| `--save`, `--load` | | Сохранение и загрузка обученных весов. |

Оба режима используют одинаковую архитектуру рекуррентного блока, одинаковое число параметров и при одинаковом seed получают одну и ту же последовательность задач. Проверочные метрики считаются на фиксированных 200 примерах, начиная с шага 0. Итоговый `testAccuracy` вычисляется на отдельном потоке задач. `lastWriteAccuracy` показывает качество правила, которое всегда возвращает значение последнего SET.

На Temurin 27 при seed 42 и 600 обновлениях, с остальными параметрами по умолчанию, получены следующие значения на 1 000 тестовых задачах.

| Режим | Точность | Cross-entropy |
| --- | ---: | ---: |
| Точная адресация | 100,0 % | 0,001181 |
| Baseline по последней записи | 45,6 % | 1,314276 |

Правило последней записи также дало 45,6 %. В режиме точной адресации проверочная cross-entropy упала с 1,389464 до 0,001212. Результат показывает, что модель научилась декодировать значение, прочитанное по заданному индексу.

Файл весов содержит число параметров и их значения. При загрузке задайте прежние `keys`, `values`, `hidden`, `steps` и режим `baseline`. При продолжении обучения состояние Adam и поток обучающих примеров создаются заново.

Бенчмарк принимает пару файлов весов в порядке «точная адресация, baseline» для конфигурации по умолчанию. Запуск без аргументов измеряет модели с начальными весами. Оба режима прогреваются и выполняют предсказания на одних и тех же 500 задачах. Замер включает затраты скалярного вычислительного графа и подходит для быстрой проверки запуска. Сравнение архитектур по эффективности потребует сопоставимых бюджетов вычислений и отдельных контрольных моделей. [Исследовательские гипотезы](research/hypotheses.md).
